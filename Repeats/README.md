# Repeat Annotation Pipeline — *Monelliopsis pecanis* (Yellow Pecan Aphid)

This document describes the repeat identification and soft-masking pipeline applied to the chromosome-scale draft assembly of the yellow pecan aphid, *Monelliopsis pecanis* (Bissell, 1983). All scripts were run on the USDA SCINet Ceres HPC cluster using SLURM.

---

## Pipeline Overview

```
01_RepeatModeler/       De novo repeat family discovery (RepeatModeler2 + LTRStruct)
02_TEtrimmer/           Automated curation and classification of the de novo TE library
03_RepeatMasker/        Soft-masking with merged de novo + known insect repeat library
```

---

## Step 1 — De Novo Repeat Discovery (`01_RepeatModeler/`)

| Script | Purpose |
|---|---|
| `RepeatModeler.sh` | Build genome database and run de novo repeat identification |

RepeatModeler2 was used to build a species-specific repeat consensus library directly from the cleaned primary assembly. The pipeline proceeds in two sub-steps.

**Step A — BuildDatabase**: A RepeatModeler-formatted genome database (`ypa_db`) was constructed from the contamination-cleaned primary assembly (`ypa_primary.cleaned.fa`) using `BuildDatabase`.

**Step B — RepeatModeler**: De novo repeat family identification was performed with `RepeatModeler` using 36 threads. The `-LTRStruct` flag was set to activate the structural LTR retrotransposon discovery pipeline (LTRHarvest + LTR_retriever), which identifies full-length LTR elements that may be missed by the sequence-similarity-based RECON and RepeatScout engines. This flag is strongly recommended for insect genomes, where LTR retrotransposons are a significant TE component.

**Primary output**: `ypa_db-families.fa` — the species-specific de novo repeat consensus library used as input for curation in Step 2.

**Key parameters**: 36 threads, `-LTRStruct`

---

## Step 2 — TE Library Curation (`02_TEtrimmer/`)

| Script | Purpose |
|---|---|
| `te_trimmer1.sh` | Automated extension, trimming, and classification of RepeatModeler consensus sequences |

De novo repeat libraries generated by RepeatModeler frequently contain partial, chimeric, or poorly bounded consensus sequences that reduce masking accuracy. TEtrimmer was used to automatically curate the `ypa_db-families.fa` library prior to masking.

TEtrimmer realigns each RepeatModeler consensus sequence back to the genome, extends boundaries to include complete terminal repeats, trims non-TE flanking sequence, and classifies elements using Pfam domain signatures (provided via `--pfam_dir`).

**Key parameters**:

| Flag | Value | Purpose |
|---|---|---|
| `-i` | `ypa_db-families.fa` | Raw RepeatModeler consensus library |
| `-g` | `ypa_primary.cleaned.fa.gz` | Reference genome for consensus extension |
| `--dedup` | — | Remove redundant consensus sequences |
| `--min_blast_len` | 60 | Minimum BLAST alignment length for extension |
| `--classify_unknown` | — | Classify elements lacking a RepeatModeler-assigned class using Pfam |
| `--pfam_dir` | `/project/tgl_seqdata/databases/pfam` | Pfam HMM database for domain-based classification |
| `-t` | 32 | Threads |

**Primary output**: curated TE consensus library for use in RepeatMasker.

> **Environment note**: TEtrimmer was run inside a dedicated Conda environment (`conda activate TEtrimmer`) activated within the SLURM job, rather than via a module. `$CONDA_PREFIX/bin` is prepended to `$PATH` to ensure the compute node uses the correct binaries.

---

## Step 3 — Repeat Masking (`03_RepeatMasker/`)

| Script | Purpose |
|---|---|
| `RepeatMasker.sh` | Merge repeat libraries and soft-mask the final assembly |

RepeatMasker was run in three logical sub-steps within a single script.

**Step 3.1 — Extract curated Insecta repeats via FamDB**: Known repeat families for all Insecta (ancestors and descendants) were extracted from the bundled RepeatMasker library (`RepeatMaskerLib.h5`) using `famdb.py`. Sequences were exported in named FASTA format (`--format fasta_name`) with repeat class included in the header (`--include-class-in-name`).

**Step 3.2 — Merge repeat libraries**: A unified repeat library (`unified_repeats.fa`) was assembled by concatenating:
1. The curated de novo RepeatModeler/TEtrimmer consensus library (`consensi.fa`)
2. FamDB-extracted Insecta families (`insecta_known.fa`)
3. RepBase v31.07 supplemental libraries: `simple.ref`, `drorep.ref` (Drosophilidae), `angrep.ref` (Anopheles/Culicidae), and `pseudo.ref` (pseudogenes/simple repeats)

**Step 3.3 — RepeatMasker soft-masking**: RepeatMasker was run against the final primary assembly using the unified library and the NCBI BLAST engine (`-e ncbi`). Soft-masking (`-xsmall`) converts repeat-overlapping bases to lowercase while preserving sequence identity, producing an assembly compatible with repeat-aware gene prediction tools (e.g., AUGUSTUS, MAKER). A GFF2 repeat annotation file was generated alongside the masked FASTA.

**Key parameters**:

| Flag | Value | Purpose |
|---|---|---|
| `-threads` | 36 | Parallel search threads |
| `-e ncbi` | — | Use RMBlast (NCBI BLAST) search engine |
| `-lib` | `unified_repeats.fa` | Custom merged repeat library |
| `-xsmall` | — | Soft-mask repeat regions (lowercase) |
| `-gff` | — | Output GFF2 repeat annotation |
| `-dir` | `$WORK_DIR` | Write all output to working directory |

**Primary outputs**:
- `ypa_primary.cleaned.fa.masked` — soft-masked assembly (lowercase repeats)
- `ypa_primary.cleaned.fa.out.gff` — GFF2 repeat annotation
- `ypa_primary.cleaned.fa.tbl` — summary table of repeat content by class

## Methods — For Manuscript Inclusion

> **For inclusion in manuscript. Citations should be replaced with formatted references.**

### Repeat identification and masking

Repetitive elements were identified and soft-masked in the final primary assembly using a three-step pipeline combining de novo discovery, library curation, and homology-based masking.

First, a species-specific repeat consensus library was generated with RepeatModeler2 [CITE: Flynn et al. 2020]. The primary assembly was formatted as a RepeatModeler database with `BuildDatabase`, and de novo repeat families were identified using RECON, RepeatScout, and the `–LTRStruct` structural pipeline for full-length LTR retrotransposon discovery. This produced a raw consensus library of 
*M. pecanis*-specific repeat families (`ypa_db-families.fa`).

Second, the de novo library was curated with TEtrimmer [CITE: Qian et al. 2025]. TEtrimmer extended each consensus sequence to complete terminal repeat boundaries by re-aligning against the genome, removed redundant sequences (`--dedup`), and classified previously unclassified elements using Pfam domain signatures (`--classify_unknown`; `--min_blast_len 60`; 32 threads).

Third, RepeatMasker [CITE: Smit et al. 2013–2015] was used to soft-mask the assembly with a unified repeat library composed of: (1) the curated de novo *M. pecanis* consensus sequences, (2) curated Insecta repeat families extracted from the RepeatMasker database (RepeatMaskerLib.h5) via FamDB [CITE: Hubley et al.], and (3) supplemental RepBase v31.07 [CITE: Bao et al. 2015] libraries for simple repeats, Drosophilidae, Culicidae, and pseudogenes. RepeatMasker was run using the RMBlast search engine (`-e ncbi`) in soft-masking mode (`-xsmall`), converting repeat-overlapping nucleotides to lowercase while retaining their sequence identity for downstream annotation. A GFF2 repeat annotation file was produced alongside the masked assembly.

### Suggested citations

> Bao, W., Kojima, K.K. & Kohany, O. (2015). Repbase Update, a database of repetitive elements in eukaryotic genomes. *Mobile DNA*, 6, 11.

> Flynn, J.M. *et al.* (2020). RepeatModeler2 for automated genomic discovery of transposable element families. *Proceedings of the National Academy of Sciences*, 117(17), 9451–9457.

> Smit, A.F.A., Hubley, R. & Green, P. (2013–2015). RepeatMasker Open-4.0. http://www.repeatmasker.org.

> Qian, J. *et al.* (2025). TEtrimmer: a tool to automate the manual curation of transposable elements. *Nature Communications*, 16, 8429.

## HPC Environment

All jobs were submitted to the **USDA SCINet Ceres HPC cluster** via SLURM. RepeatModeler and RepeatMasker were loaded as modules (`module load repeatmodeler`, `module load repeatmasker`). TEtrimmer was run within a dedicated Conda environment (`conda activate TEtrimmer`). Large memory allocations (250 GB) were required for RepeatMasker genome-wide alignment. Intermediate files were written to the `/90daydata/` scratch filesystem.
