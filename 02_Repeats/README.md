# Repeat Annotation Pipeline — *Monelliopsis pecanis* (Yellow Pecan Aphid)

Workflow describing the repeat identification and soft-masking pipeline for the draft assembly of the yellow pecan aphid, *Monelliopsis pecanis* (Bissell, 1983). All scripts were run on the USDA SCINet Ceres HPC cluster using SLURM.

---

## Pipeline Overview

```
01_RepeatModeler/              De novo repeat family discovery (RepeatModeler2 + LTRStruct)
02_TEtrimmer/                  Automated curation of the de novo TE library
03_RepeatMasker/               Merge the de novo + RepBase libraries and soft-mask the genome
04_RM_Report_Top6Scaffolds/    ProcessRepeats report for the six chromosome-scale scaffolds
05_Repeats_Fixed_Windows/      Fixed-window TE/genetic-diversity pipeline
```

---

## Step 1 — De Novo Repeat Discovery (`01_RepeatModeler/`)

| Script | Purpose |
|---|---|
| `RepeatModeler.sh` | Build genome database and run de novo repeat identification |

RepeatModeler2 was used to build a species-specific repeat consensus library directly from the cleaned primary assembly. The pipeline proceeds in two steps.

**Step A — BuildDatabase**: A RepeatModeler-formatted genome database (`ypa_db`) was constructed from the contamination-cleaned primary assembly (`ypa_primary.cleaned.fa`) using `BuildDatabase`.

**Step B — RepeatModeler**: De novo repeat family identification was performed with `RepeatModeler`. The `-LTRStruct` flag was set to activate the structural LTR retrotransposon discovery pipeline (LTRHarvest + LTR_retriever), which identifies full-length LTR elements that may be missed by the sequence-similarity-based RECON and RepeatScout engines.

**Primary output**: `ypa_db-families.fa` — the species-specific de novo repeat consensus library used as input for curation in Step 2.

**Key params**: 36 threads, `-LTRStruct`

---

## Step 2 — TE Library Curation (`02_TEtrimmer/`)

| Script | Purpose |
|---|---|
| `te_trimmer1.sh` | Automated extension, trimming, and classification of RepeatModeler consensus sequences |

De novo repeat libraries generated by RepeatModeler frequently contain partial, chimeric, or poorly bounded consensus sequences that reduce masking accuracy. TEtrimmer was used to automatically curate the `ypa_db-families.fa` library prior to masking.

TEtrimmer realigns each RepeatModeler consensus sequence back to the genome, extends boundaries to include complete terminal repeats, trims non-TE flanking sequence, and classifies elements using Pfam domain signatures (provided via `--pfam_dir`).

**Key parameters**:

| Flag | Value | Purpose |
|---|---|---|
| `-i` | `ypa_db-families.fa` | Raw RepeatModeler consensus library |
| `-g` | `ypa_primary.cleaned.fa.gz` | Reference genome for consensus extension |
| `--dedup` | — | Remove redundant consensus sequences |
| `--min_blast_len` | 60 | Minimum BLAST alignment length for extension |
| `--classify_unknown` | — | Classify elements lacking a RepeatModeler-assigned class using Pfam |
| `--pfam_dir` | `/project/tgl_seqdata/databases/pfam` | Pfam HMM database for domain-based classification |
| `-t` | 32 | Threads |

**Primary output**: curated TE consensus library for use in RepeatMasker.

> **Environment note**: TEtrimmer was run inside a dedicated Conda environment (`conda activate TEtrimmer`) activated within the SLURM job, rather than via a module. `$CONDA_PREFIX/bin` is prepended to `$PATH` to ensure the compute node uses the correct binaries.

## Step 3 — Repeat Masking (`03_RepeatMasker/`)

| Script | Purpose |
|---|---|
| `RepeatMasker.sh` | Extract FamDB Insecta families, merge repeat libraries, and soft-mask the assembly |

**Step 3.1 — Extract curated Insecta repeats via FamDB**: Known repeat families for Insecta were extracted from the bundled RepeatMasker library (`RepeatMaskerLib.h5`) using `famdb.py`. Sequences were exported in FASTA format (`--format fasta_name`) with repeat class included in the header (`--include-class-in-name`).

**Step 3.2 — Build unified repeat library**: A unified library (`unified_repeats.fa`) was constructed by concatenating three source inputs:

1. The curated de novo RepeatModeler/TEtrimmer consensus library (`consensi.fa`)
2. FamDB-extracted Insecta families (`insecta_known.fa`)
3. Four targeted files from RepBase v31.07:

| RepBase file | Repeat type | Taxonomic group | Selection rationale |
|---|---|---|---|
| `drorep.ref` | Multiple TE types | *Drosophila* spp. (Insecta) | Best-characterized insect TE library in RepBase; broadly representative of Class Insecta TE diversity |
| `angrep.ref` | Multiple TE types | *Anopheles gambiae* (Insecta) | Second major insect reference; captures TE families absent or underrepresented in the Drosophila library |
| `simple.ref` | Macrosatellites / simple tandem repeats | Cross-taxonomic | Required for masking microsatellites and simple sequence repeats in any genome |
| `pseudo.ref` | Retroposed pseudogenes | Cross-taxonomic | Captures processed pseudogene insertions that can confound gene prediction if left unmasked |

The complete merge command:

```bash
cat "$MODELER_OUT" \
    insecta_known.fa \
    "${REPBASE_DIR}/simple.ref" \
    "${REPBASE_DIR}/drorep.ref" \
    "${REPBASE_DIR}/angrep.ref" \
    "${REPBASE_DIR}/pseudo.ref" > unified_repeats.fa
```

**Step 3.3 — RepeatMasker soft-masking**: RepeatMasker was run against the final primary assembly using the unified library and the NCBI BLAST engine (`-e ncbi`). Soft-masking (`-xsmall`) converts repeat-overlapping bases to lowercase. A GFF repeat annotation file was generated alongside the masked FASTA.

**Key parameters**:

| Flag | Value | Purpose |
|---|---|---|
| `-threads` | 36 | Parallel search threads |
| `-e ncbi` | — | Use RMBlast (NCBI BLAST) search engine |
| `-lib` | `unified_repeats.fa` | Custom merged repeat library |
| `-xsmall` | — | Soft-mask repeat regions (lowercase) |
| `-gff` | — | Output GFF repeat annotation |
| `-dir` | `$WORK_DIR` | Write all output to working directory |

**Primary outputs**:
- `ypa_primary.cleaned.fa.masked` — soft-masked assembly
- `ypa_primary.cleaned.fa.out.gff` — GFF repeat annotation
- `ypa_primary.cleaned.fa.tbl` — summary table of repeat content by class

## Step 4 — Chromosome-Scale Repeat Report (`04_RM_Report_Top6Scaffolds/`)

| Script | File | Purpose |
|---|---|---|
| `process_repeats.sh` | — | Generate repeat summary tables for the top 6 scaffolds |
| — | `top6_names.txt` | Scaffold IDs for the six chromosome-scale sequences, ordered by size |

*M. pecanis* has 6 apparent chromosomes. The final draft assembly contained nine scaffolds, with the six largest representing putative chromosome-scale sequences. Because the full-genome RepeatMasker run processed all scaffolds, `ProcessRepeats` was used to regenerate the repeat statistics table restricted to the six chromosomal scaffolds using the pre-computed `.cat` alignment file (`ypa_primary_top6.fa.cat`).

`ProcessRepeats` recomputes the RepeatMasker summary statistics from an existing alignment archive without re-running the BLAST search, making it efficient for subsetting. The `-excln` flag excludes low-complexity and simple repeat regions from the statistics, and `-maskSource` provides the original unmasked genome FASTA for coordinate reference.

**Key parameters**:

| Flag | Value | Purpose |
|---|---|---|
| `-lib` | `combined_refined_aphid_repeats.fa` | Repeat library used in the original masking run |
| `-maskSource` | `ypa_primary.fa` | Unmasked genome FASTA for coordinate reference |
| `-excln` | — | Exclude low-complexity/simple repeat statistics from the summary |

**Input**: `ypa_primary_top6.fa.cat` — RepeatMasker alignment archive subset to the top 6 scaffolds

**Primary outputs**:
- `ypa_primary_top6.fa.tbl` — repeat content summary table for the six chromosomal scaffolds
- `ypa_primary_top6.fa.out` — detailed repeat annotation for the six scaffolds

## Step 5 — Transposable Element Effects on Genetic Diversity

After chromosome-scale repeat annotation (Step 4), a fixed-window analysis tested whether TE presence, TE order/class, and TE age (Kimura divergence) are associated with local nucleotide diversity (π) across the genome.

### Fixed-window pipeline (`05_Repeats_Fixed_Windows/`)

| Script | Purpose |
|---|---|
| `00_extract_kimura_align.sh` | Run [`circos/extract_kimura_align.py`](../circos/extract_kimura_align.py) to parse per-insertion Kimura values and repeat annotations |
| `01_make_fixed_windows.sh` | Build non-overlapping 5 kb and 10 kb genome-wide windows and annotate each with overlapping TE content |
| `02_calc_pi.sh` | Calculate windowed nucleotide diversity with VCFtools `--window-pi` and join to the TE annotations |
| `06_q3b_brms.R` | Exploratory extension of q3: random slopes of TE age by TE class |
| `06_make_figures.R` | Conditional-effects plots and a combined multi-panel figure |

**Step 5.1 — Kimura extraction ([`circos/extract_kimura_align.py`](../circos/extract_kimura_align.py))**: This is the parser used to generate the Kimura dataset for Bayesian regression modeling. Each RepeatMasker `.align` block reports the query scaffold, insertion coordinates, matching repeat name, class/family (encoded as `name#Class/Family`), and Kimura-2-parameter divergence corrected for CpG hypermutability (`Kimura (with divCpGMod)`). The script writes a self-contained TSV with repeat size, Smith-Waterman score, percent divergence/deletion/insertion, adjusted and unadjusted Kimura values, CpG-site count, repeat class, collapsed repeat order, and TE presence. No join to the RepeatMasker `.out` file is required.

**Step 5.2 — Fixed-window construction (`01_make_fixed_windows.sh`)**: Non-overlapping 5 kb and 10 kb windows were tiled across all six chromosome-scale scaffolds using `bedtools makewindows`. Each window was intersected against the TE coordinate table (`bedtools intersect -wao`) and annotated with total TE base-pair coverage, TE fraction, TE presence/absence, the set of overlapping TE orders/classes/families, and the mean Kimura divergence of overlapping TEs.

**Step 5.3 — Diversity calculation (`02_calc_pi.sh`)**: Nucleotide diversity was calculated for the same fixed windows using VCFtools [CITE: Danecek et al. 2011] `--window-pi`, and the resulting per-window statistics (`N_VARIANTS`, `N_MONOMORPHIC`, `PI`) were joined to the TE annotation table by window coordinates.

**Step 5.4 — Bayesian modeling**: The primary model scripts are documented in [`05_Regression_Models/`](../05_Regression_Models/README.md). Nucleotide diversity was modeled as a function of TE presence, TE fraction, TE order, TE class, and TE age using `brms` [CITE: Bürkner 2017] and Stan, assuming a lognormal distribution for π and including chromosome as a covariate.

**Step 5.5 — Figures (`06_make_figures.R`)**: Conditional-effects estimates from each fitted model were extracted and plotted individually and as a combined multi-panel figure.

## HPC Environment

All jobs were submitted to the **USDA SCINet Ceres HPC cluster** via SLURM. RepeatModeler and RepeatMasker were loaded as modules (`module load repeatmodeler`, `module load repeatmasker`). TEtrimmer was run within a dedicated Conda environment (`conda activate TEtrimmer`). Large memory allocations (250 GB) were required for RepeatMasker genome-wide alignment. Intermediate files were written to the `/90daydata/` scratch filesystem.
